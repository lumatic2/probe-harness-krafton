# M0 — 세팅 (오케)

## 핵심 4줄
- 목표: 과제 원문을 보존한 채 킷을 작업 공간에 깔고 첫 커밋을 남긴다
- 종료 조건: `scaffold` 커밋 · 세팅 보고 ①~④ 전달 · 스킬이 목록에 보인다(`$` 목록에 안 잡히면 `.agents/skills/<이름>/SKILL.md` 를 직접 읽으면 된다고 보고에 적는다) · **작업 방식 실측 ①②④ 를 과제설정 7절에 적고 ③ 을 사용자에게 요청했다**(③ 판정은 설명 세션이 열린 뒤 — 그때까지 B)
- 담당: 오케
- 증거: `scaffold` 커밋 · 세팅 보고 · `docs/세션.txt` 오케 줄

## 세팅 요청
1. 레포를 작업 공간 안 `probe-harness-krafton/` 에 클론한다. 못 찾거나 clone 이 막히면 URL 을 지어내지 않고 사용자에게 알린다.
2. `bash probe-harness-krafton/setup.sh` 를 **고치지 않고 그대로** 돌린다. setup.sh 는 작업 공간 밖에 아무것도 쓰지 않고, 지우는 것은 작업 공간 안의 클론 폴더뿐이다 — 「이 안에서만」 지침과 부딪히지 않으니 일부를 빼거나 복사본을 만들어 돌리지 않는다.
3. setup.sh 출력 맨 끝 「다음(에이전트)」 지시를 그대로 따른다 — 세팅 뒤 할 일의 정본은 그 출력 하나다. 세팅 보고에는 보고 ①~④ · 스킬 확인 줄(`$` 에 handoff 가 보이나 — **안 잡히면 `.agents/skills/<이름>/SKILL.md` 를 직접 읽는다**고 그 줄에 함께 쓴다) · **설명 탭 여는 문장**(A·B 둘 다) · **작업 방식 실측 요청**(아래) · `다음 입력(오케): 「과제 시작하자」` 가 다 들어간다.

## 작업 방식 실측 (세팅 직후 — 시험 Codex 가 앱이어서 CLI 전제가 맞는지 확인한다)
세팅 보고를 전한 같은 턴에 아래 네 가지를 한다. 결과는 `docs/과제설정.md` 7절 「작업 방식」 칸에 적는다(방법·판정은 루트 `Codex-앱-조작.md` 2절을 사용자에게도 가리킨다).
1. **①** 에이전트가 `which codex && codex --version` 을 돌려 결과를 적고, 사용자에게 「앱 터미널(``Ctrl+` ``)에서도 같은 명령을 쳐서 결과를 알려 주세요」(사람 터미널 결과가 기준 — 에이전트 셸과 다를 수 있다).
2. **②** 에이전트가 `echo "${CODEX_THREAD_ID:-없음}"` 를 실행해 값을 적는다(setup 출력 2번의 세션 등록과 같은 값). `/status` 의 chat ID 와 같은지는 사용자가 본다.
3. **③** ①이 될 때만. 설명 세션(두 번째 세션)이 `docs/세션.txt` 에 등록된 뒤, 거기서 얻은 ID 로 오케가 `codex queue --thread <설명 ID> --message "ping"` 을 보내고 **사용자가 설명 세션 화면에 ping 이 뜨는지 본다**(종료 코드가 0 이어도 안 뜰 수 있다 — 화면이 기준).
4. **④** 컨텍스트 % 가 늘 보이는지 사용자에게 묻는다(안 보이면 `/status` 로 40%·50% 확인).
- **판정: ①②③ 다 되면 A(터미널 CLI), 하나라도 안 되면 B(앱 chat). 판정 전에는 B.** 판정을 과제설정 7절에 쓰고 사용자에게 한 줄 알린다. B 이면 이후 모든 「queue」 는 우편함(`AGENTS.md` 「세션 등록」)이다.

다음 신호 「과제 시작하자」 → `M1-과제설정.md`.
