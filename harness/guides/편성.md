# 편성.md — 새 탭 안내 · 입력 요령 · 승계 문장 (에이전트가 사용자에게 안내할 때 읽는다)

> 사람이 치는 당일 순서는 킷 밖(준비 레포의 D-day 체크리스트)에 있다. 이 파일은 오케가 탭 안내·승계 안내를 할 때 가리키는 정본이다.

## 탭과 모델

모델·effort 는 사용자가 하면서 정한다 — 킷은 지정하지 않고, 오케는 안내에 `/model` 까지만 쓴다. 서브에이전트는 오케 세션 모델을 그대로 쓴다. 서브에이전트도 탭도 오케가 제안하고 사용자가 승인해야 늘어난다.

**동시 세션(탭) 수 상한은 시험마다 다르다** — 세팅 때 확인해 `docs/과제설정.md` 5절에 적고(서브에이전트가 상한에 포함되는지도 함께 — 모르면 「미확인」), 탭 편성은 그 상한 안에서 한다. 늘리려는 편성이 상한을 넘으면 어느 탭을 합칠지는 사용자에게 묻고 `$decision` 한 줄.

처음엔 오케 · 설명 · DM 으로 시작한다. 그 밖의 탭은 일이 커져 병목이 생길 때 오케가 「어느 탭을 · 왜」를 제안하고 사용자가 정해 위 상한 안에서 연다(늘릴 후보: 통합 · 검증 · 코어 · 화면 · 필요시 서비스). 통합은 서버를 살려 두고 화면 QA 재빌드에 바로 답하는 탭이라 오래 걸리는 일(E2E · 전량 실행 · Docker · 실행 재현)은 검증 탭이 맡는다 — 한 탭이 계속 일하느라 다른 탭이 기다리면 그 탭의 일을 갈라 새 탭을 연다. 오케에 실행 일이 몰리면 검증 워커에 넘긴다. 새 탭 안내 한 줄: `탭 이름 <이름> → codex → /permissions Full Access → /model → 붙이기: 「AGENTS.md와 .agents/skills/handoff/SKILL.md, docs/brief/<역할>.md 를 읽고 <역할> 워커로 시작해」`. 브리프는 파일이다 — 「준비됨」 queue 는 등록 확인이라 답하지 않는다. **설명 탭 안내 한 줄**(세팅 보고 때 — 빠졌으면 언제든 다시): `새 탭 → codex → /permissions Full Access → /model → 「harness/roles/설명.md 읽고 역할 파악해. 이 세션은 설명 세션으로 쓸 거야」 → 탭 이름 설명`.

**방식 A/B** (`docs/과제설정.md` 7절 — 실측 4단계는 `Codex-앱-조작.md` 2절. 판정 전에는 B):
- **A 일 때**: 위 문장 그대로. 「새 탭」은 **앱 내장 터미널(``Ctrl+` ``)의 새 터미널 → `codex`** 로 읽는다.
- **B 일 때**: 탭 = 사이드바 chat. 새 탭 안내 한 줄은 `새 chat(Ctrl+N 또는 /new) → Codex 모드·Local 확인 → 입력창 아래 권한 컨트롤 Full access(없으면 Ask for approval) → /model → 붙이기: 「…」 → Ctrl+Alt+R 로 이름 <역할>` 이다(붙이는 문장은 위와 같다). 설명 chat 도 같은 꼴. 세션 간 전달은 `codex queue` 대신 **우편함**(`AGENTS.md` 「세션 등록」) — 오케가 안내 때마다 `<역할> chat 에 「우편함」` 한 줄을 덧붙인다.
- 컨텍스트: 상시 % 표시가 없으면 사람이 단계 경계마다 `/status` 로 본다(40% 근처 승계 준비 · 50% 넘으면 불신은 그대로). 넘으면 `/compact` 를 쓸지 새 chat 으로 갈지는 오케가 사용자에게 한 줄 묻는다.

## 입력 요령 (확인된 것)
- Codex 입력칸 줄바꿈은 **Ctrl+J**(B 일 때: 앱에서 Ctrl+J 는 아래 패널 토글이다 — 입력창 줄바꿈 키는 `Ctrl+/` 로 확인하고, 긴 지시는 우편함·파일에 쓴다). Shift+Enter·역슬래시는 안 된다. 긴 여러 줄 지시는 파일에 쓰고 경로만 넘긴다(`docs/mail/` 또는 `메모.md` 밖의 임시 파일).
- 스킬 목록(`$`)이 안 보이면 `/quit` → `codex resume`(B 일 때: 연 폴더가 작업 공간 루트인지 확인 → 새 chat). 그래도 없으면 `.agents/skills/<이름>/SKILL.md` 를 직접 읽는다. 전역 등록(`python3 harness/tools/install_skills.py --workspace .`)은 작업 공간 밖에 쓰므로 사용자가 시킬 때만.
- 플랫폼 Browser 는 **포트 칸 `3000` · 경로 칸 `/`**. 전체 URL 을 넣으면 깨진다.
- (A 만) 터미널 스크롤이 멈추면 그 탭에서 `/quit` → `codex resume <UUID>`(화면에 뜨는 문장 그대로). **그 사이 들어온 queue 는 보존되어 재개 뒤 순서대로 처리된다**(Codex 0.163·0.166 확인). 바쁜 탭에 사용자가 직접 치면 쌓인 queue 보다 먼저 답한다.

## 승계 문장 (사용자가 「승계하자」를 치면 오케가 `$handoff` 뒤 이 문장을 출력하고, 사용자가 새 탭에 붙인다 — 상태줄 `context-used` 40% 근처면 준비, 50% 전에 단계 경계에서 · 새 탭 모델·effort 는 사용자 선택. **B 일 때**: 「새 탭」 = 새 chat — 아래 문장을 새 chat 에 붙이고 이름은 Ctrl+Alt+R 로 `오케`. 옛 오케 chat 에 「우편함」을 치지 않는다)

```
AGENTS.md 와 harness/roles/오케.md, .agents/skills/handoff/SKILL.md 「이어받기」, docs/HANDOFF.md 를 읽고 오케를 이어받아. 지금 상황 3줄 · 다음 할 일 1개 · 종료까지 남은 시간을 말하고, 「이어받기」의 새 오케 절차(편지함 → 세션.txt 오케 줄을 새 UUID 로 교체 → 살아 있는 탭에 「오케 바뀜」)를 한 뒤 기존 범위에서 계속해.
```

## 컨텍스트
compact 는 상태가 파일에 다 들어간 순간에만(권장: 「설계 OK」 뒤 브리프 발행 직후 = 승계, M5 끝 = compact). 상태줄의 컨텍스트 사용량을 사람이 본다(B 일 때 상시 표시가 없으면 `/status`).
